## 专辑上映日期与目录命名（2026-11-17）

## 最新实现：任意一集暂停一次后，独立请求其他剧集（2026-11-17）

用户进一步要求：与腾讯视频工具一致，客户端只需打开任意正片并暂停一次；之后跨集、跨电视剧下载均只提供链接，不允许逐集或逐剧切换可见播放器。以下为最新设计和证据，后面的 11 月 16 日章节保留历史调查过程。

- 使用 `QyPlayer.exe` 中已初始化、已登录的 `mctoplayer.dll`，通过独立 `CreateMctoProgramsManager` 包装器及 `PushFront` 生成指定 TVID 的播放预读请求；不是离线下载派发。程序不调用 `DownloadEx`、下载设置或播放器导航接口。
- 当前版本的 packed 输入长度、字段偏移和字符容量已由原生调用方及真实输入核对。输入从零初始化，只填写明确核验的 TVID、公开 VID、收费标记、档位、HDR、帧率、扩展参数等，离线标记保持零；不能复制当前窗口的输入，否则其中缓存的播放响应可能阻止新请求生成。
- 请求前查询既有预读状态，目标已经存在则拒绝接管。捕获自己的完整 QTP 响应后，只删除本次创建的临时节目，确认状态消失再销毁包装器。原生登录上下文留在客户端，不重新登录、不导出账号凭据。
- 原生请求及响应必须严格对应目标 TVID。当前正式来源直接使用捕获到的完整原生响应，不额外 HTTP 重放；媒体 CDN 只带公开媒体头。临时媒体地址、`mk`、`ms` 和 DRM ticket 不写入报告。
- 用户确认“已暂停”后，针对当前清单三个电视剧分别通过独立 SDK 请求完成前、中、后分段的授权处理与解码：`session_20261117_001825_716368.json`、`session_20261117_001833_531781.json`、`session_20261117_001843_796066.json`。这些测试没有打开或切换目标播放页，包含当前暂停集以及另外两个电视剧。

- 旧格式按照物理文件名从 `mk` 对应签名。新格式在 `uea=1`、清单已有 `qd_tc/qd_rt/qd_etd/qd_tvid` 时，追加响应 `ms` 中的原始查询字段；不必解开 `eak`。不能将第一物理文件的 CDN 地址模板替换到后续文件。

- HTTP Range 是字节范围的明确协议，原地址中的 `start/end/contentlength` 在构造请求时移除，保留其他授权参数。核对实际长度及存在时的 `Content-Range`，拒绝服务端忽略范围或返回另一区间。
- 部分正常 HLS 分段超过抽样上限。正式下载按已校验清单的目标长度流式写盘，使用主配置 `copy_buffer_bytes`，不沿用抽样字节上限。临时文件只有长度及响应范围通过后才能重命名为完成分段，SHA-256 随流式读取计算，网络截断仅保留未完成现场。
- 正式入口为 `download_iqiyi.py --config configs/playback.yaml`，模块位于 `qsv_local/playback/`。支持公开短链接、分享页和普通播放页，逐任务/清单全局/主配置的 `all-parts` 优先级、官方正片目录分页、重复任务去重及集序过滤。
- 普通 `/v_*.html` 页的页面正文可能只有 SPA 壳；TVID 按已安装 qysdk 的 base36/XOR 规则计算，常量配置在专项 YAML。结果还需经公开节目资料和原生响应再次核对。
- `quality` 按各集原生声明的画质组排名；同档合并 HDR/编码变体，不按媒体大小排名。选档后必要时重新请求指定来源，严格核对 VID、档位、非试看授权、完整清单及正片时长。未支持格式、缺少授权或请求不符时失败，不暗中替换或降档。
- 本次正式能力限定为用户要求的 `quality: 1`。额外试验中，同分辨率的次高 SDR 组仍返回最高增强源；修改 SDK 输入、原生 VRS 参数和同域响应重放的优先级均未证明可以精确切换，因此不保留这些未验证的参数改写，未开放次高排名。其他排名在 SDK 请求前明确拒绝，不能将最高源误报为次高源。
- 同一来源的分段断点需重新计算长度及 SHA-256 才能复用；稳定身份包含 TVID、来源 VID、SDK 摘要、物理路径摘要、范围、时长和总大小，不包含临时签名。正式成品侧记使用独立的 `schema_version` 和 `record_type`，并重新计算成品摘要后才复用。

### 适配边界

当前 SDK 结构和偏移仅适用于专项配置摘要对应的本机 Windows x64 客户端。支持 HLS AVC/HEVC，以及新增的 DASH SegmentList AV1/CENC、独立 AMP4 音轨；独立 AAC 已完整解码验证，其他编码以真实返回及验证为准。完整媒体验证复用本机授权、无损封装、全片解码、视频 PES/MP4 样本数和复制摘要检查。客户端升级后需重新核验 ABI，不能只修改摘要。

## 11 月 16 日目标与阶段结论（历史）

用户已明确：采用“链接 + 已登录播放会话 / 播放界面缓存”，由脚本获取媒体并输出到指定目录，**客户端不能创建离线下载列表任务**。不采用 `DownloadEx` 派发路线。以下早期章节保留当时的观察，当前结论以本节为准。

### 已验证的播放缓存路径

- 当前客户端的播放器位于 `QyPlayer.exe`，播放缓存引擎位于另一个 `QyKernel.exe`；主界面 `QyClient.exe` 并不承载全部播放模块。研究进程通过安装目录、进程名及实际加载模块辨认，不固定 PID。
- 已找到 `temp_cache` 下的 PGF 数据文件和 `data.db`、`data-qsv.db`、`data-nor.db` 及 WAL/SHM。普通 Python SQLite 打开缓存索引会报 `file is not a database`；不能当普通 SQLite 复制后直接读取，也不能忽略 WAL。
- 已从 `HCDNClientNet.dll` 的 RTTI、数据库包装器调用方和实测交叉核对 `CPgfDBManager`、已打开的数据库句柄和内置 SQLite 查询 ABI。通过该句柄执行固定的只读 `SELECT`，可以访问主 PGF 索引，无需导出数据库密钥或改写缓存文件。
- 实测索引包含 `T_FILE_INFO`、`T_BLOCK_INFO` 和 `T_PGF_PATH`，可对应 TVID、具体视频来源 VID、片段序号/总数、声明文件大小、缓存块序号、块大小、CRC、物理块位置和 PGF 文件。**文件存在、文件声明大小和片段记录存在均不能证明缓存完整**，需要核对每段全部块。
- 当前链接集的快照中，《一生一世》第 30 集有第一段的前 3 个连续块，合计 6 MiB，该来源声明 9 段，第一段本身也不完整；《周生如故》第 4 集仅残留另一个来源第一段的第 59 块；主 PGF 索引中未找到《七时吉祥》第 1 集。它们均不足以直接输出整集。此结论只针对本次主 PGF 索引快照，不代表其他索引或后续播放没有数据。

## 对照腾讯视频 URL 流程的进一步调查

- 腾讯工具的 URL 模式通过已初始化播放器读取原生登录态及生成签名，再自行获取清单和下载；它与客户端缓存还原是两个来源。爱奇艺适配不能直接复用腾讯的接口、结构或签名。
- 本机爱奇艺客户端 `14.9.0.10269` 的内置网页调用 `Download.getDashInfo({tvid, bid: ""})` 查询下载媒体信息；将下载任务列表送入 `Download.excute({data_list, appmode})`。SDK 将后者映射到客户端命令 `DownloadEx`。这些是静态代码观察，不代表已从外部脚本成功调用。
- 这些命令通过 `window.localWebApp.getHandler("iqiyi/pca")` 和 WebView2 的 `chrome.webview.postMessage` 交给客户端处理；普通外部 Python 进程没有该网页桥接对象。探测到的客户端回环端口没有提供 Chromium 的 `/json/version` 调试接口。客户端窗口控制工具无法接管该窗口，因而尚未验证原生桥接的外部调用、返回值、认证与 4K 下载任务。
- 涉及的客户端文件 SHA-256：`CubeDownload.dll` 为 `cb92f6b6f766eea6d973f2e3ee6875690c0152d23bf6041a7e9295dd1173a1c8`，`DownloadCenter.dll` 为 `fe10094312adafb371cf92d417e01759293a921c58f3a5569d9f1e8578990bb1`，`LocalWebApp.dll` 为 `c70d0b21a0f8540465a393410f8097b18ec622105ca13d78e574a8ec849c3f62`。这些摘要仅标识本次静态研究对象，不构成 ABI 或兼容性验证。
- 待解决：验证只读登录态和原生签名/授权的稳定接口，或者验证客户端桥接可由外部安全调用；取得目标集真实可下载档位、完整资源与授权；再实现清单展开、最高档选择、下载、断点、转换、完整解码验证及发布。上述任一项未完成前，不能将 URL 模式标为可用。
