# 工具工作区

使用 VS Code 打开 [001_获取B站的视频.code-workspace](001_获取B站的视频.code-workspace)。

B 站视频工具的使用顺序：

1. 在“终端 → 运行任务”中选择“B站：准备环境”。
2. 运行工作区任务“B站：打开 Cookie 导出工具”。在已登录 B 站的默认 Chrome 中打开 `chrome://extensions`，开启“开发者模式”，点击“加载已解压的扩展程序”，选择任务打开的 `chrome_cookie_export` 文件夹。
3. 点击 Chrome 扩展菜单中的“B站登录态本机导出”，保存到工具目录的 `cookies` 文件夹。选择工作区“B站：验证 Chrome 登录态”确认可用；若保存到其他目录，在 `config.yaml` 的 `auth.cookie_file` 中修改路径。
4. 选择“B站：查看画质与字幕”“B站：下载当前分 P”或“B站：下载全部分 P”，按工作区提示输入链接。登录过期后重新点击扩展导出即可。

工作区默认读取工具目录的 `config.yaml`；下载时原样复制音视频编码，字幕独立保存。默认下载链接指定的分 P，无分 P 参数时下载第一 P。运行环境、入口及参数均在 workspace 文件中维护。

不属于合集的视频按投稿标题和 BV 号保存在 `001_获取B站的视频/downloads/标题_BV号/` 下；属于 B 站合集的视频直接并排保存在 `downloads/合集标题_合集编号/` 中。同一合集的不同 BV 视频和同一投稿的各分 P 均可分次增量下载到对应目录，视频和字幕直接放在该目录。各分 P 的断点流保存在 `.streams/BV号_p序号/` 中，互不干扰。文件名通过下划线连接 BV 号或分 P 标识，全部分 P 拼接结果命名为 `标题_BV号.mp4`（或 `.mkv`），不额外添加“完整版”文字、方括号或连接用的空格。自动拼接仅由命令行参数控制：`--auto-merge-parts` 在全部分 P 下载成功后自动按顺序无损拼接，省略或传入 `--no-auto-merge-parts` 时关闭；YAML 不再配置此开关。工作区“B站：下载全部分 P”的 `args` 默认使用 `--no-auto-merge-parts`，需要自动拼接时改为 `--auto-merge-parts`。下载单个分 P 或投稿总共只有一个分 P 时不会触发自动拼接。原分 P 和字幕会保留，字幕不拼接。不同编码或分辨率的分 P 不会强行拼接。

要手动拼接已经下载的分 P，在“运行和调试”选择“B站：拼接已下载分 P”，输入 BV 号或普通 BV 视频链接，然后输入可选的分 P 范围。范围留空时拼接全部分 P，要求从 P1 到最后一 P 均已下载完成；旧记录没有总集数时，只能检查已有分 P 是否从 P1 连续，需自行确认最后一 P 已下载。手动拼接无需登录，也不受自动拼接开关影响；旧版下载目录中的分 P 同样可以使用。拼接结果保存在标题目录，已存在同名结果时不会覆盖。修改配置后重新运行对应启动配置即可生效。

指定范围时，使用逗号连接片段、`起点-终点` 表示包含首尾的范围、分号分隔不同输出组。例如 `1-5,8,10-12;10-12` 生成 `标题_BV号_p1-5_p8_p10-12.mp4` 和 `标题_BV号_p10-12.mp4` 两份文件（包含 MKV 分 P 时输出 `.mkv`）。严格按输入顺序拼接，不排序、不去重：`3,1,3` 依次拼接 P3、P1、P3，`10-12,1-5` 先拼 P10～P12 再拼 P1～P5。编号必须为正整数，允许分隔符两侧有空白；范围起点不能大于终点，每组至少包含两个片段，重复项计入数量。

命名只压缩相邻递增编号，保留倒序和重复项；同一批次中相同序列第二次起追加 `_2`、`_3`。名称或路径超长时报告该组失败，不截断编号序列。各组只检查所选分 P 的完成状态、真实文件及编码兼容性，未选择的分 P 不影响该组。非法表达式、空组、缺失或未完成的分 P、编码不兼容、同名输出及运行错误均单独报告，其余组继续；最后汇总每组的输入、输出或失败原因，全部成功返回 `0`，存在失败返回 `2`。原分 P、字幕及已成功的拼接文件均保留。

在工作区根目录用 Windows PowerShell 执行分组拼接（替换为已下载视频的 BV 号）；整个表达式必须放在引号中，避免分号被终端解释为命令分隔符：

```powershell
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" ".\001_获取B站的视频\download_bilibili.py" --config ".\001_获取B站的视频\config.yaml" --merge-video "BV1o1JB69Eua" --merge-parts "1-5,8,10-12;10-12"
```

“B站：下载全部分 P”也提供范围输入框：输入分组表达式后，下载结束即按指定分组拼接，优先于自动拼接开关，即使未启用 `--auto-merge-parts` 也会执行。某个分 P 下载失败时仍尝试各组，已完成的所选分 P 可以正常拼接，包含失败分 P 的组单独报错；下载或拼接存在失败时退出码为 `2`。范围留空时，仅传入 `--auto-merge-parts` 才会在全部下载成功后拼接全部分 P。

`--merge-parts` 可与 `--merge-video` 或下载模式的 `--all-parts` 同用。手动拼接时省略或留空表示拼接全部分 P；下载全部分 P 时省略或留空遵循命令行自动拼接开关。工作区范围输入框对应此参数。

每个投稿独立记录视频信息：普通投稿使用 `video_info.json`，合集目录中的投稿使用 `BV号_video_info.json`，避免不同投稿互相覆盖。记录保存原视频地址、标题、BV 号、UP 主、总分 P 数，以及各分 P、拼接结果和旧版独立视频的文件信息。文件条目包含状态、相对路径、大小（字节）、时长（秒）、分辨率、帧率、音视频编码、保存时间和用于续传及拼接的格式签名；保存时间取文件修改时间，时间字符串包含时区。缺失的信息写为 `null`，原因记录在 `errors` 中。本地媒体参数来自已配置的 FFmpeg，帧率和时长精度以其文件头报告为准。

下载合集中的任一投稿时，工具根据原站返回的合集编号复用对应合集目录，并将成员列表中已下载的旧投稿、字幕、断点流和记录迁入该目录；遇到同名目标会报错，不覆盖文件。不同合集分别保存；若同一 BV 号存在多份投稿记录，工具会报错并要求整理。也可以将完整投稿目录手动移入其他分组文件夹，工具仍会查找已有投稿。此行为不改变“下载全部分 P”的含义：它下载当前 BV 的所有分 P，不会自动下载整个合集。

每份拼接结果使用独立的记录标识，并保存 `source_parts` 编号列表，例如 `[3, 1, 3]`，完整保留顺序和重复项；旧记录无需迁移，现有信息文件版本保持不变。

解析投稿后、传输开始前创建记录，在分 P 开始、完成、失败或中断以及拼接完成时原子更新；不会随每个下载数据块频繁写盘。再次运行时按完成状态、格式签名和真实文件判断是否跳过下载。旧 `download.json` 中的必要信息会先合并到该文件，写入并核对成功后删除，不再生成或保留旧记录副本；迁移失败会报错并保留尚未迁移的原记录。

已有下载可在“运行和调试”选择“B站：补生成视频信息”，或者在工作区根目录用 Windows PowerShell 执行：

```powershell
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" ".\001_获取B站的视频\download_bilibili.py" --config ".\001_获取B站的视频\config.yaml" --refresh-metadata
```

该模式扫描配置的下载目录，不需要视频链接，兼容分 P 子目录和投稿目录直接存放视频的结构，不重新下载视频，也不执行拼接。访问已有投稿时，会将旧 `BV号_p序号` 子目录中的视频和字幕移到投稿目录，将断点流移到按分 P 隔离的目录，同步更新对应信息文件路径并移除搬空的子目录；下载、手动拼接和补生成信息时都会按需整理。合集归档在下载合集成员时触发。文件名保持原样，遇到同名目标会报错且不覆盖，移动或记录保存失败时回滚已移动的文件。`--refresh-metadata` 与登录检查、画质列表、手动拼接模式互斥，不能与 `--url` 或 `--all-parts` 同用。UP 主等信息复用当前认证方式查询原站；原站查询失败仍保存可确认的本地信息，并以退出码 `2` 报告未完成项。续传与拼接统一读取投稿的信息文件，手动拼接仍可离线运行。

测试脚本统一放在 `001_获取B站的视频/tests/`，共用测试包中的项目资源路径。工作区已配置 unittest 以工具目录为工作目录和导入根目录，从 `tests` 发现用例，可通过 VS Code 测试面板运行。在工作区根目录用 Windows PowerShell 运行全部测试：

```powershell
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" -m unittest discover -s ".\001_获取B站的视频\tests" -t ".\001_获取B站的视频" -v
```

测试使用模拟原站响应、本地 HTTP 服务及 FFmpeg 短视频；Chrome 导出用例使用临时无头浏览器，不读取真实账号或下载目录。
