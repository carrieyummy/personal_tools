# 工具工作区

使用 VS Code 打开 [001_工具.code-workspace](001_工具.code-workspace)。

B 站视频工具的使用顺序：

1. 在“终端 → 运行任务”中选择“B站：准备环境”。
2. 运行工作区任务“B站：打开 Cookie 导出工具”。在已登录 B 站的默认 Chrome 中打开 `chrome://extensions`，开启“开发者模式”，点击“加载已解压的扩展程序”，选择任务打开的 `chrome_cookie_export` 文件夹。
3. 点击 Chrome 扩展菜单中的“B站登录态本机导出”，保存到工具目录的 `cookies` 文件夹。选择工作区“B站：验证 Chrome 登录态”确认可用；若保存到其他目录，在 `config.yaml` 的 `auth.cookie_file` 中修改路径。
4. 选择“B站：查看画质与字幕”“B站：下载当前分 P”或“B站：下载全部分 P”，按工作区提示输入链接。登录过期后重新点击扩展导出即可。

工作区默认读取工具目录的 `config.yaml`；下载时原样复制音视频编码，字幕独立保存。默认下载链接指定的分 P，无分 P 参数时下载第一 P。运行环境、入口及参数均在 workspace 文件中维护。

视频按投稿标题和 BV 号保存在 `001_获取B站的视频/downloads/标题_BV号/` 下。投稿总共只有一个分 P 时，视频和字幕直接保存在该目录；总共有多个分 P 时，各分 P 使用独立子目录，即使只下载其中一个分 P 也保留该子目录。文件名通过下划线连接 BV 号或分 P 标识，拼接结果命名为 `标题_BV号.mp4`（或 `.mkv`），不额外添加“完整版”文字、方括号或连接用的空格。配置文件 `download` 中的 `auto_merge_parts: true` 可在全部分 P 下载完成后自动按顺序无损拼接，当前配置已开启；单分 P 下载不会触发自动拼接。原分 P 和字幕会保留，字幕不拼接。不同编码或分辨率的分 P 不会强行拼接。

要手动拼接已经下载的分 P，在“运行和调试”选择“B站：拼接已下载分 P”，输入 BV 号或普通 BV 视频链接。手动拼接无需登录，也不受自动拼接开关影响；旧版下载目录中的分 P 同样可以使用。旧记录没有总集数，只能检查已有分 P 是否从 P1 连续，需自行确认最后一 P 已下载。拼接结果保存在标题目录，已存在同名结果时不会覆盖。修改配置后重新运行对应启动配置即可生效。

每个投稿目录只有一份 `video_info.json`，同时保存原视频地址、标题、BV 号、UP 主、总分 P 数，以及各分 P、拼接结果和旧版独立视频的文件信息。文件条目包含状态、相对路径、大小（字节）、时长（秒）、分辨率、帧率、音视频编码、保存时间和用于续传及拼接的格式签名；保存时间取文件修改时间，时间字符串包含时区。缺失的信息写为 `null`，原因记录在 `errors` 中。本地媒体参数来自已配置的 FFmpeg，帧率和时长精度以其文件头报告为准。

解析投稿后、传输开始前创建记录，在分 P 开始、完成、失败或中断以及拼接完成时原子更新；不会随每个下载数据块频繁写盘。再次运行时按完成状态、格式签名和真实文件判断是否跳过下载。旧 `download.json` 中的必要信息会先合并到该文件，写入并核对成功后删除，不再生成或保留旧记录副本；迁移失败会报错并保留尚未迁移的原记录。

已有下载可在“运行和调试”选择“B站：补生成视频信息”，或者在工作区根目录用 Windows PowerShell 执行：

```powershell
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" ".\001_获取B站的视频\download_bilibili.py" --config ".\001_获取B站的视频\config.yaml" --refresh-metadata
```

该模式扫描配置的下载目录，不需要视频链接，兼容分 P 子目录和投稿目录直接存放视频的结构，不重新下载视频，也不执行拼接。确认投稿总共只有一个分 P 时，会将旧 `BV号_p1` 子目录中的视频、字幕及断点流移到投稿目录，同步更新 `video_info.json` 路径并移除搬空的子目录；正常下载时也自动整理这种旧目录。文件名保持原样，遇到同名目标会报错且不覆盖，记录保存失败时回滚移动。`--refresh-metadata` 与登录检查、画质列表、手动拼接模式互斥，不能与 `--url` 或 `--all-parts` 同用。UP 主等信息复用当前认证方式查询原站；原站查询失败仍保存可确认的本地信息，并以退出码 `2` 报告未完成项。续传与拼接统一读取 `video_info.json`，手动拼接仍可离线运行。

测试脚本统一放在 `001_获取B站的视频/tests/`，共用测试包中的项目资源路径。工作区已配置 unittest 以工具目录为工作目录和导入根目录，从 `tests` 发现用例，可通过 VS Code 测试面板运行。在工作区根目录用 Windows PowerShell 运行全部测试：

```powershell
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" -m unittest discover -s ".\001_获取B站的视频\tests" -t ".\001_获取B站的视频" -v
```

测试使用模拟原站响应、本地 HTTP 服务及 FFmpeg 短视频；Chrome 导出用例使用临时无头浏览器，不读取真实账号或下载目录。
