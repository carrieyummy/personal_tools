# 芒果视频工具设计与流程

本文记录当前实现的职责、处理流程和约束；实际运行参数以 `configs/` 中的配置及注释为准。日常操作见 [README](../README.md)。

## 目录与职责

- `download_mgtv.py`：定义和校验命令行参数，调用业务入口并处理退出码。
- `local/client.py`：正式和研究流程共用的客户端登录态、原生请求及链接处理。
- `local/tasks.py`：读取链接清单、校验正片目录、按接口顺序逐集选档。
- `local/series.py`：从同一剧集编号的官方专辑页面读取唯一完整上映日期，并在当前批次缓存。
- `local/hls.py`：读取完整媒体清单，下载分片、维护断点及原始字节证据。
- `local/media.py`：无重编码封装及全片解码验证；`local/storage.py`：指纹、锁与发布事务。
- `local/scheduler.py`：独立下载池、共享处理池及字节容量队列；`local/application.py` 和 `local/activity.py`：协调各阶段并记录状态、实时页面和离线报告。
- `local/migration.py`：在输出和工作目录专用锁保护下规划及原位整理已有剧集目录，检查冲突、同步成品索引并保留事务记录。
- `configs/` 保存正式配置，`download_list/` 保存下载清单，`tests/` 保存测试，`research/` 保存研究资料和专项配置。

## 下载与处理流程

1. 入口读取主配置及链接或 YAML 清单。`--url` 可重复，未提供时交互输入；整剧范围依次由命令行、清单、主配置决定，画质由清单或主配置决定。`--login-only` 只检查已有登录态，`--list-formats` 只查看画质，不执行下载。
2. 工具只读客户端保存的登录态，通过原生 HTTP 接口解析链接和正片目录，不读取播放日志、不操作客户端界面，也不要求逐集点击。目录按清单顺序增量展开，完整校验每部剧的分页及身份后交接；页面逐步补充发现的任务。已上线正片按集序处理，重复视频只调度一次，画质设置冲突时报错。
3. 每集按接口返回的画质组由高到低独立排名，选定账号可获取的源，并验证完整 HLS 清单和时长。指定档位不存在、调度地址无效或源不受支持时明确失败，不改用低档或 SDR 备用源。营销 HDR 描述与实际媒体属性分别记录。
4. 根据视频、源和清单身份检查已登记成品；身份一致且通过完整 SHA-256 校验的成品直接复用，跳过下载。其他任务按视频及源指纹建立独立工作现场，顺序下载单集分片并保存可验证断点。
5. 下载完成后释放下载名额，将现场交给后处理：无重编码封装、完整解码视频及预期音轨、计算指纹、发布成品并更新索引。CPU 和 GPU 各有独占验证槽，每集使用其中一个启用的后端；失败不切换设备。启用 GPU 时先检查 CUDA 初始化，具体格式仍逐集验证；不缩放、转码或进行色调映射。
6. 剧集目录使用配置模板和官方专辑完整上映日期，日期缺失、冲突或无效时失败；文件名使用集序、源站标题和实际清晰度等配置字段。不同来源保留独立版本，同名未知文件不覆盖，冲突时新成品使用区分后缀。成功后按配置清理中间文件，失败或取消保留现场。

## 并发、续签与取消

- `download.threads` 限制同时下载的剧集数，每集内顺序下载分片。目录发现、解析、复用检查、续签、封装、验证、指纹、发布和清理共用顶层 `max_in_flight` 处理上限；封装、发布及解码设备仍受各自内部槽限制。
- `download.queue_capacity_gb` 按实际字节限制下载完成后、排队等待处理的原始分片，包括初始化片段及通过校验的复用断点；不包含清单、候选 MP4、报告、下载中、等待入队、处理中及历史失败现场。容量按 1024³ 字节换算，空队列允许单集超限独占。容量不足时暂停新下载，任务开始后处理时释放队列容量；日志区分等待容量和等待后处理。
- 地址过期时释放下载名额，在处理池续签后重新排队。源身份变化时保留旧现场并重新解析；持续变化达到配置的重试上限后停止该集。
- 单集失败继续其他集；登录失效停止派发新下载，已下载任务继续后处理。Ctrl+C 回收线程池与子进程，记录已接纳任务的终态并保留断点；取消返回 130，参数错误返回 2，其他失败返回 1。

## 格式、记录与隔离

- 支持带 ENDLIST 的点播 TS/fMP4、字节范围及主清单独立音轨。加密 HLS 的授权还原机制尚未验证，遇到时明确报错；暂不支持拼接。
- FFmpeg 使用主配置指定的可执行文件，当前适配包含 FFmpeg 9 的本地 HLS 扩展校验参数，不搜索其他程序兜底。至少启用 CPU 或 GPU 中的一个完整验证后端。
- 实时页面仅监听本机回环地址；历史 JSON 和带时间戳的离线 HTML 按官方专辑名称分组，每集记录由公开编号生成的播放页面链接。`logging` 中的日志、索引和锁文件名必须保留 `mgtv_` 或 `.mgtv_` 前缀，与共享输出目录中的其他工具隔离。
- `configs/native_playback.yaml` 维护协议版本、能力协商与状态约束；能力声明用于请求原码流，不代表显示器或硬件已经通过对应格式验证。客户端路径、登录态和其他本机参数按用途保存在正式或研究配置中；不预设需要调用客户端 DLL。

## 研究与验证

- `research/playback_probe.py` 使用 `research/configs/playback_research.yaml`，支持结构检查、原生接口探测、选集查询、静态接口定位及隔离的播放器能力查询，不操作客户端界面。`research/configs/source_selection_research.yaml` 用于源选择对比，通过 `research/selection_probe.py` 的 `--variants` 显式传入。
- `research/query_player_caps.ps1` 提供 32 位播放器能力查询；调用前校验已验证 DLL 的 SHA-256，辅助进程不接收登录票据。
- `tests/verify_playback_api.py` 为实网接口验收，验证目标画质、完整 HLS 清单及抽样分片解码；脱敏报告和媒体样本写入已忽略的 `research/results/`，不保存登录票据或带签名媒体地址。`tests/accept_download.py` 是显式单集全片验收，包含下载、完整解码、发布及第二次指纹复用。
- 普通 `unittest` 发现测试使用临时目录、回环 HTTP 和合成媒体，不访问真实账号。`tests/benchmark_media.py` 对已登记且指纹一致的成品比较串行和并发完整解码；报告注明是否包含下载与发布，解码阶段比值不等同于端到端下载加速。研究及验收产物写入调用方指定的已忽略目录。

原有 PowerShell 示例均以工具目录为当前目录，解释器以工作区设置为准：

```powershell
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" "download_mgtv.py" --url "download_list/download_list.yaml"
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" -m pip --proxy "" install -r "requirements.txt"
```

`PyYAML` 为正式依赖，`capstone` 用于既有二进制研究。清单中的 `date` 和 `commit` 是备注，不用于生成媒体目录。
