# 腾讯播放画质与交付调查

本记录是 2026-11-16 对当前清单的实测证据，不是固定的视频规格或配置默认值。运行参数以 `configs/` 下实际 YAML 为准。

## 整剧首次上映日期（2026-11-17）

公开整剧简介卡片 `pc_introduction` 的子项包含 `report.cid`、`title` 和 `broadcast_time`，应核对专辑编号与剧名后读取完整日期，不使用 `hollywood_online` 或单集更新时间。当前本地目录实测：《永夜星河》2024-11-01、《交锋》2026-09-06、《花开锦绣》2026-08-09，与各剧公布的首播日期一致。日期字段以腾讯当前整剧资料为准，其他片源是否与其他平台的最早首播完全一致需分别核验。

## 限速与签名的对照

- 网页协议签名能查询到 MAX 档位及完整清单，但多个 CDN、urllib/curl、不同请求头、HTTP/HTTPS 和显式代理对照中，媒体持续约 1 KB/s。仅增加能力声明或改成原生接口域名，没有解决该现象。
- 用户已确认 SVIP，客户端能播放 MAX。客户端交给下载代理的原生地址，首个 64 KB 能在约 0.08–0.33 秒内读完。
- 播放器子进程向原生代理播放接口发送 JSON POST。已将 SDK `h` 导出的签名输出与两个真实播放请求的 cKey 完整匹配，匹配位置为 0、长度为 1130；原文只存在内存。
- 同一 `h` 接口也处理心跳：视频编号为空、末尾参数为包含 `cmd` 的 JSON 时，返回两段长度头与载荷。心跳结果不能当播放 cKey。真正播放调用的视频编号非空、末尾参数为空，返回直接签名字符串。
- 参数 6 是 int32 数组，参数 7 是数量，本次观察为单个零值；此前将它当空字符串或整数语义推断并不正确。
- 独立加载 DLL 的隔离对照返回错误码 `-1`；在已初始化的运行播放器上下文中调用同一 ABI 能生成签名。正式流程因此要求客户端播放器保持运行，不使用独立加载失败结果，也不回退网页签名。
- 采用原生 SDK 签名重新请求同一集 MAX 后，三个 CDN 均返回完整的 64 KB 范围数据，耗时约 0.06–0.19 秒；账号响应被接受，尺寸及帧率与 MAX 相符。该结果证明吞吐差异与请求协议/SDK 上下文相关，不能归因于用户会员等级不足。
- 正式接入对照还确认：签名和播放请求必须使用运行播放器已初始化的设备 GUID，不能每次随机构造。已静态核对 TVKPlayer 的只读上下文布局，并校验该 DLL 的摘要；设备标识只在内存传递。统一使用实际 GUID 后，同档接口及三个 CDN 的有界传输再次通过。

DLL 摘要、输出长度边界、同一 CRT 的 free 导入位置及一次性会话参数统一在 `configs/native_signing.yaml` 维护。能力字段及 SDK 编码版本号在 `configs/native_playback.yaml` 维护；不在此文档复制为运行默认值。

## 音质边界

音质与画质分别选择。音质依据主配置 `audio.quality` 对每集实际可授权、可归档的原始音源排名，`1` 为最高，`2` 为次高。无法下载的项及播放器滤镜不计入排名，无需终端交互；指定排名不存在时明确失败。

客户端“清澈人声”等由播放器滤镜实时实现，不是独立可下载的音源，不能把标准 AAC 原轨命名为该 VIP 效果。当前下载来源报告只记录实际原始音源，音效协议结构保留在研究资料中。

原生响应的 `al.ai` 在本集只含一个已选“标准”条目：格式编号与视频相同，没有独立文件、键或地址。这是视频中复用的原轨描述；代码已严格核对该结构，不能因为字段名像音轨列表就当作独立下载，也不能忽略真正的独立音源。`afl.afi` 则明确返回“清澈人声”的实时滤镜参数及 VIP 标记，这部分不生成下载音质选项。

## 复现

以下为 PowerShell，工作目录是本工具根目录。先在客户端播放已授权正片，保持唯一播放器运行。

```powershell
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" -X utf8 research/probe_native_key.py --config configs/playback_research.yaml
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" -X utf8 research/probe_native_key.py --config configs/playback_research.yaml --local-only
```

第一条检查实际播放响应及有界分片传输；第二条故意独立加载 DLL，用于诊断初始化依赖。要仅核对运行中 SDK 的签名结构，可为第二条追加 `--pid <已核对的播放器编号>`。

完整单集验收使用 `tests/verify_playback.py`，清单序号按用户当前清单填写。只有完整下载、媒体属性检查、全片解码、发布及第二次复用均通过，才可标记全片验收成功；有界传输成功不能替代这一步。

CPU/GPU 在正式流水线中是验证设备资源池，每集使用其中一个。需要同一成品在所有当前启用设备上通过时，使用 `tests/verify_url_output.py --config configs/config.yaml --report <单集全片报告> --report-dir research/results` 补验，报告同时核对成品 SHA-256。

## 已完成的本机验收

- 《花开锦绣》第 08 集：270 个资源，清单时长 2692.288 秒；完整下载约 146.7 秒，无损封装后为 HEVC 3840×1606、60 帧、10bit，标准 AAC 48 kHz 立体声。
- GPU 与 CPU 都完成 161534 帧全片解码，结束时间均为 2692.288 秒，退出码均为 0。成品发布到主配置指定目录，第二次运行校验摘要后复用，没有重复下载。设备补验前后的成品摘要一致。
- 本片没有写明色域和传递函数，不能仅凭“臻彩 MAX”认定为 HDR。
- 《交锋》链接集的最高档与完整清单查询通过：3840×1634、60 帧，278 个资源，时长 2763.05 秒，标准原轨，同源续签匹配。
- 《永夜星河》实际返回“标准”“立体环绕”“清澈人声”三项，后两项为 VIP 实时效果；历史验收时旧版按阈值触发交互，用户选择标准原轨。当前版本只将标准原轨作为可下载音源，按 `audio.quality` 自动选择。链接对应第 32 集，MAX 为 3840×1606、60 帧；完整清单 266 个资源、2628.33 秒，同源续签匹配。本项完成接口与清单验收，未执行全片下载。
- 音质按每集实际可下载的音源排名选择，不再缓存终端选择；只有标准原轨时，逐集内容评分变化不会产生额外音质档位或交互。
- 完整单集及设备报告位于本机已忽略的 `research/results/`，不提交媒体、签名或账号数据。
