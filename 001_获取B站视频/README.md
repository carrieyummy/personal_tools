# 工具工作区

使用 VS Code 打开仓库根目录中的 [001_获取B站视频.code-workspace](../001_获取B站视频.code-workspace)。

B 站视频工具的使用顺序：

1. 在“终端 → 运行任务”中选择“B站：准备环境”。
2. 运行工作区任务“B站：打开 Cookie 导出工具”。在已登录 B 站的默认 Chrome 中打开 `chrome://extensions`，开启“开发者模式”，点击“加载已解压的扩展程序”，选择任务打开的 `chrome_cookie_export` 文件夹。
3. 点击 Chrome 扩展菜单中的“B站登录态本机导出”，保存到工具目录的 `cookies` 文件夹。选择工作区“B站：验证 Chrome 登录态”确认可用；若保存到其他目录，在 `config/config.yaml` 的 `auth.cookie_file` 中修改路径。
4. 选择“B站：查看画质与字幕”“B站：下载当前分 P”或“B站：下载全部分 P”，输入链接或 YAML 清单路径。普通投稿和单季在终端选择画质上限；开启全部关联季时，同一番剧只选择一次逐集档位排名。清单按配置确定上限，各 P 自动选择上限内的最高可用档位。登录过期后重新点击扩展导出即可。

工作区和命令行默认读取工具目录的 `config/config.yaml`；下载时原样复制音视频编码，字幕独立保存。下载范围由该配置和命令行、清单实际设置决定。配置中的相对路径以 `config` 目录为基准，`../` 指向工具根目录；本次迁移已调整下载和 Cookie 相对路径，继续使用原有目录。运行环境、入口及参数均在 workspace 文件中维护。

同时支持番剧 `/bangumi/play/ep编号`、`/bangumi/play/ss编号` 链接、裸 `ep`/`ss` 号以及指向这些地址的 b23.tv 分享链接。关闭 `download.all_seasons` 时，下载范围按现有配置、清单和命令行优先级确定：未开启全部下载时，`ep` 下载指定集，`ss` 下载第一集；开启 `--all-parts` 或有效的 `all-parts` 设置后，下载该季全部正片。整季按原站正片列表编号，不按剧集标题中的数字排序，也不把预告、花絮等附加分区混入正片。显式输入附加内容的 `ep` 链接时，可单独下载并以 EP 号归档；对该链接开启全部下载仍选所属季正片。

需要通过一个番剧地址下载所有季时，在 `config/config.yaml` 的现有 `download` 节点将 `all_seasons` 设为 `true`。此独立开关不改变普通 BV/AV 下载；对番剧按原站关联季列表顺序、以季编号去重展开，每季下载全部正片，优先于 `all_parts`、命令行 `--all-parts` 和清单 `all-parts`。列表中作为独立季提供的番外篇、特别篇、长征篇等同样包含；某季内预告、花絮等附加分区不下载。缺少有效关联季列表时明确报错，不静默缩小为单季；列表为空时只处理当前季。

各季以原站标题和真实 `ss` 编号分别归档；混合画质模式的源目录为 `季标题_ss编号_分P/`，关闭混合画质时再按实际画质分目录。普通链接展开全部关联季时，同一番剧只确认一次**档位排名**：`1` 表示每集可用的最高档，`2` 表示每集第二高档，按各集实际可下载的平台档位编号降序排名，不锁定某个画质编号，也不使用各季档位并集排名。例如第一季某集最高只有 1080P、第二季某集支持 4K，选 `1` 时分别下载 1080P、4K。刷新播放流时仍按所选排名重新选档；某集没有该排名则单独报错，不自动改选其他排名。重复 ep/ss 输入共用一次确认，不同番剧分别确认；`s` 跳过本番剧全部关联季，`q`、EOF 或 Ctrl+C 取消运行。选择只对本次运行有效。

清单不弹菜单，仍为每季按该项 `quality` 和本季目标 P 的档位并集确定上限。`merge-parts` 的范围在每季内分别生效，不跨季拼接，合并结果另存对应 `_合并` 目录。拼接优先策略在各集所选档位范围内选择兼容版本，已规划的拼接版本刷新时仍锁定画质及编码。某季查询或下载失败会单独报告，其他季继续，最终返回未全部完成；已成功的文件可在重试时复用。此开关也作用于画质列表查询，登录检查、补生成信息和离线拼接仍保持各自范围。

例如 `ep311310` 属于 `ss28541` 的 P10。关闭 `all_seasons` 且未启用全部下载时，单独下载仍保留 P10，与后续整季下载共用记录并复用已完成媒体。番剧以“季标题_ss编号”为基础目录，沿用当前 `download.mix_quality` 的实际画质布局；共用线程池、断点续传和下载后拼接规则。以下命令在本工具目录下用 Windows PowerShell 执行，登录、输出路径、画质策略及字幕设置均读取实际配置：

```powershell
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" ".\download_bilibili.py" --url "https://www.bilibili.com/bangumi/play/ep311310?from_spmid=666.25.episode.0"
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" ".\download_bilibili.py" --url "ss28541" --all-parts --merge-parts "0"
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" ".\download_bilibili.py" --merge-video "ss28541" --merge-parts "1-3;4-6"
```

`--list-formats` 和 YAML 清单同样支持番剧。PGC 播放流按每集真实 EP/CID 查询，字幕使用每集真实 AV/CID；试看、DRM 或无观看权限的剧集明确报错，不登记为完整下载。番剧断点在原有画质/CID/格式隔离规则内增加 EP 层级，避免换集后混用。单集失败保留其他集的成功结果，包含缺失集的拼接组失败或跳过，其他可用组继续。季列表变化时同时核对 EP 和 CID，避免复用到同一编号下的另一集。番剧没有普通投稿的 UP 主字段时，记录为 `null`，不因此判定下载失败。

索引使用统一的 `source_type` 和 `source_id`：普通投稿标识为真实 BV，番剧正片为 `ss编号`，独立附加内容为 `ep编号`；番剧季顶层 `bvid` 为 `null`，每集保留自己的真实 BV/AV、EP 和原始地址。源索引版本为 v8，合并索引为 v2；已有普通投稿按需升级，保留文件名、来源指纹和历史结果。补生成信息可识别番剧季；离线拼接接受已下载的 `ss` 号或季链接，无需登录。

原始流下载与后处理采用两个独立线程池，配置均从 `config/config.yaml` 读取：`download.threads` 限制同时下载的分 P 数，顶层 `max_in_flight` 统一限制逐项解析、选档、复用检查及后处理的总并发数，两者必须为正整数。所有输入按清单和参数顺序优先派发当前投稿，空闲下载线程由后续投稿补位；单个分 P 内顺序传输各流，不叠加分片线程池。准备阶段在共享处理池中使用独立 HTTP 会话，原浏览器对象不跨线程；确认成品可复用后直接进入处理队列，不占下载名额。原始流下载结束即释放下载名额，封装、指纹计算、快速媒体探测、发布、字幕处理及投稿拼接收尾共用后处理上限，下载与后处理可以同时进行。投稿所需分 P 结算后即可进入同一后处理池收尾，不必等待其他投稿；同一投稿内部的拼接组仍顺序执行。独立手动拼接保持现有顺序流程。

`download.queue_capacity_gb` 按实际原始流大小限制“已下载且等待后处理”的容量，1 GB = 1024³ 字节，必须是有限正数且折算后至少为 1 字节；缺少配置或非法值会报错。空队列允许一个超容量分 P 独占，进入后处理时释放容量。解析、复用和等待入队均不占下载名额；等待队列积压时暂停新下载，预解析缓存也有界。`download.threads` 是活动媒体下载数的上限，并非保证持续满载。容量不包含下载中、等待入队、处理中及历史失败断点，不是整个下载目录的磁盘限额。网页分别显示“等待队列容量”和“等待后处理”，后处理完成前不会标记该分 P 成功。

主线程负责登录、交互选择画质排名或上限，并提取可跨线程使用的认证快照；目录发现、归档初始化及画质预查询进入共享处理池；逐项刷新地址和复用检查在共享处理池中执行，准备、传输及后处理各自使用独立 HTTP 会话。记录按来源标识加锁更新，网络传输和媒体工具在记录锁外执行。封装和拼接始终保留原始编码，媒体探测只快速读取信息；本工具不新增 CPU/GPU 完整解码验证，当前处理不需要 GPU 解码。取消时停止两池派发、回收网络和媒体进程，等待任务退出，保留原始流和断点；重跑继续按现有来源版本、格式和成品复用规则处理。

`download.http_chunk_size_bytes` 控制单次 HTTP 范围请求的最大字节数，必须为非负整数；正数启用分块，`0` 关闭主动分块。下载器始终读取配置实际值，缺项或非法值明确报错。遇到 CDN 大响应提前截断时可减小该值，提高传输成功率；分块越小，请求次数越多。正常完成的分块不消耗下载失败重试次数，重新运行仍可从已有 `.part` 文件继续传输；分块大小与 `fragment_retries` 的分片失败重试次数分别配置。

每个投稿的分 P 全部处理结束后立即进入共享处理池收尾，同一投稿内的合并组顺序执行，无需等待其他投稿；合并期间下载池继续工作。下载后的拼接使用本任务各 P 的实际档位，不再弹出合并画质菜单；每组仍必须使用同一实际画质，编码和分辨率也须兼容。离线拼接仍可交互选择本地实际档位。

`download.priority` 必须填写 `quality`（清晰度优先）或 `merge`（拼接优先），缺项、空值和其他值均报错。初始配置为 `quality`，程序始终读取配置实际值。两种策略都先为每个 BV 确定一次画质上限：清单 `quality` 按该任务目标 P 的档位并集排名，普通链接由用户选择；不会让其他 BV 拉低当前 BV 的上限。普通番剧链接展开全部关联季时改为共用一次逐集档位排名选择，各集独立选档，拼接优先在各集所选档位以内寻找兼容方案。

- `quality`：全部关联季的普通番剧链接按每集所选排名下载，其他任务取上限内的最高档位；拼接时检查实际来源是否兼容。
- `merge`：对每个拼接组独立选择逐集所选档位或原有上限以内的最高兼容档位，并在同档位内寻找流结构、音视频编码和分辨率一致的选流方案；候选仍受 `download.format` 和 `download.format_sort` 约束，不自动转码。全量拼接 `0` 视为一个组。未启用拼接、或不属于任何拼接组的目标 P，按清晰度优先下载。

例如 `1-3;2-4` 的两组分别选择 4K、1080P 时，P2 和 P3 各下载两个画质；若两组同为 1080P 但分别需要 AVC、HEVC，也保留两个编码版本。相同来源版本只传输一次，可供多个组和重复任务复用。新增版本的源标识包含完整格式摘要，文件名用 `_fmt摘要前12位` 区分版本；命名冲突明确报错，字幕跟随对应文件，断点按 CID 和格式参数隔离。已有相同格式和 CID 的有效媒体可直接复用，保留原文件名。

某组在上限内没有兼容方案时，仍下载该组各 P 的最高可用画质，记录该组拼接失败，继续其他组和其他 BV，最终返回 `2`。派发前刷新地址时，已规划版本的画质、编码、尺寸和帧率必须仍可用；消失则报告该版本失败，不独自换档破坏组内兼容性，重新运行时重新规划。在线拼接明确引用各组所需版本；离线模式同画质存在多个编码版本时，按组筛选本地共有兼容方案，单方案自动使用，多方案交互选择。

实时日志为每个下载版本单独显示画质、编码、进度及所属拼接组，分别统计独立 P 数和下载版本数。源索引升级为 v8，增加 `format_variant` 字段；旧索引按记录格式升级，保留 CID、指纹和原媒体，格式未知的文件不推断为已确认版本。合并索引升级为 v2，成品与运行结果新增有序的 `source_entries` 来源引用，原有来源内容快照和覆盖策略继续生效。

下载或离线拼接时，程序自动启动本地日志服务，终端打印 `http://127.0.0.1:端口/`，在 Chrome 打开该网址查看实时状态。默认每 2 秒获取内存中的最新数据，局部更新时保留筛选、运行展开状态及滚动位置；可以同时打开多个标签页。浏览器不读取正在写入的持久化日志，因此不会因查看页面占用日志文件而阻止替换。服务只监听本机回环地址，端口默认自动分配，每次运行以终端打印的网址为准。

页面面向电脑浏览器，按“每次运行 → 任务 → 下载/合并 → 分 P/合并组”展示树形任务表，点击分 P 或合并组在表格下方查看详情。任务可以独立展开、折叠；实时刷新保留筛选、展开状态和选中项。页面保留历次运行，可按标题、BV 号、分 P、错误原因搜索，也可只看失败、中断和提示；筛选时保留所属任务和阶段。内容包含实际画质、封装及字幕状态、复用结果、成品链接和失败原因。只验证登录、查看画质及补生成媒体信息不会创建下载日志。

任务分别显示下载就绪数量和合并进度，预先列出本次任务需要执行的合并组。分 P 进度条标明当前音频或视频流，100% 仅表示当前流完成，视频和字幕处理结束后该分 P 才计入就绪数量。合并通过 FFmpeg 实时进度按已处理媒体时间计算百分比；来源时长未知时显示活动进度条，不估造百分比。日期时间统一为 `YYYY:MM:DD HH:MM:SS`，例如 `2026:11:15 14:30:05`；已耗时和预计剩余时间为 `HH:MM:SS`，超过一天保留累计小时，无法估算时显示 `--:--:--`。下载、合并及任务分别计时，排队中的活动尚未开始计时；离线快照、已结束记录及断线后的页面固定在最后记录状态。

平均速度统一为十进制 `MB/s`（1 MB = 1,000,000 字节），下载按本次实际传输字节除以音视频流有效传输时长，已有断点字节、流间等待、封装和字幕处理不计入；完成后保留最终平均速度。任务下载均速汇总子项字节，对并发传输时间区间取并集，避免重复计时。合并单独显示已输出字节除以 FFmpeg 执行时间的平均处理吞吐量，不混入下载速度。

命令行在确定下载版本后显示各文件大小、任务合计和本次运行合计，完成或复用时显示实际文件大小。网页表格的“文件大小”列显示每个下载版本的大小，详情分别列出整文件预计大小和实际大小；任务行显示该任务／季的合计，运行概览显示本次运行去重后的目标视频总大小。搜索、异常筛选和折叠不改变合计范围。实时页面及离线报告使用相同数据，旧日志没有大小记录时显示“未知”。

预计大小只使用实际选中音视频流已有的文件长度或估算值，不额外发送 HEAD、Range 等长度查询，也不根据码率自行推算。所选流长度都已知才显示整文件预计大小；含估算值时明确标注“约”，未知值不按零处理。下载过程中可由现有进度回调补齐长度；流切换、重试和断点续传只修正对应流，不重复累加。无损封装完成后，以最终文件的实际字节数为准，预计大小与实际大小可能略有差异。大小采用十进制 MB／GB，保留两位小数。

总大小统计本次目标视频的完整大小，包含已下载并复用的文件，表示目标内容大小而非剩余网络流量或磁盘峰值。同一来源、分 P、EP、CID、实际画质及编码版本只计一次；不同画质或编码分别计入。字幕、临时流及合并产物不重复计入下载目标合计，合并行单独展示其成品大小。部分文件大小未知时显示“已知合计”和未知文件数量；失败、中断或尚未下载的目标保留已知预计大小。每个任务独立汇总，本次运行再跨任务去重，因此重复任务的合计不能直接相加。

日志设置集中在 `config/config.yaml` 的 `logging` 中：`state_file` 默认为输出根目录的 `download_log.json`，保存历次运行；`port` 为本地服务端口，`0` 自动选择空闲端口；`refresh_interval_seconds` 控制页面轮询；`progress_interval_seconds` 控制传输进度最小写盘间隔，默认 1 秒。状态切换及结果立即原子保存，Windows 文件占用时按 `write_retries` 和 `write_retry_interval_seconds` 有限重试（默认 5 次、间隔 0.2 秒）。持续失败只提示，最新状态仍在网页可见，下载及合并继续；恢复后保存最新完整状态。日志历史损坏时明确报错并保留原数据，不覆盖未知内容。

运行正常结束、失败或取消后，先保存最终 JSON 和离线快照，再保持日志服务可用，等待近期活跃网页拉取并显示最终状态。每个标签页分别确认本次运行及最终版本，全部确认后立即关闭服务；没有网页访问时直接关闭。等待上限读取 `logging.final_state_timeout_seconds`，要求大于 0，建议覆盖至少一次 `refresh_interval_seconds` 轮询间隔；网页已关闭、断网或无响应时，到达上限后提示并退出，最终结果以离线快照为准。最近访问时间在轮询间隔与等待上限两者较大值以内的页面参与确认，长期停止轮询的旧页面不阻止退出。页面收到终态后显示“运行已结束 · 当前为最终状态”，不再轮询，避免服务关闭后仍停留在“封装及字幕处理”等旧状态。

`html_file` 作为离线快照的命名基准。每次运行结束，自动在配置的文件名前缀后追加本地导出时间 `yymmdd_hhmmss`，例如前缀为 `download_log` 时生成 `download_log_261115_134820.html`；运行中点击页面“导出 HTML”也使用此规则。同秒重复导出或已有同名文件时追加 `_01`、`_02` 等序号，并发创建冲突也会换序号重试，保留已有报告。每份快照内嵌全部数据，离线打开不联网、不刷新，后续运行不覆盖它，因此旧快照保持在 Chrome 打开也不妨碍新日志保存。首次运行新版本时，如果 JSON 尚不存在，则只读导入配置基准 HTML 文件的历史，保留旧文件；已结束运行中残留的“下载中”等状态修正为“已中断”，已有真实失败保留。已有带随机标识的快照保留原名。请以新一轮日志判断续传和重试结果。

按一次 Ctrl+C 后，程序提示“正在停止并保存断点”，停止派发新任务及重试，取消运行中的下载、字幕、封装、分 P 合并和媒体探测。活动 HTTP 读取会中断；尚未建立响应的连接仍受现有请求/连接超时约束。已启动的 FFmpeg 会终止，按 `runtime.process_terminate_timeout_seconds` 等待（默认 2 秒），超时后强制回收；`runtime.cancel_poll_interval_seconds` 控制检查间隔（默认 0.1 秒）。原始流、断点和已有成品保留，未完成临时媒体清理。重复按 Ctrl+C 不打断清理；工作线程及媒体子进程退出、网页确认最终状态（或等待超时）、本地日志服务关闭后，才显示“已中止”并返回 `130`。正常收到最终状态的网页显示“运行已结束”；超时断线时保留最后收到的数据，可查看离线快照。程序退出后不再更新日志。再次使用同一条命令运行，会复用已确认的成品并重试失败、未完成的分 P。

终端保留登录、画质交互、任务节点及错误摘要，下载时不再重复输出完整格式表和逐数据块进度；“查看画质与字幕”仍完整列出格式。

`--url` 可传视频/番剧链接、BV/AV 或 ep/ss 号、本地 `.yaml`/`.yml` 下载清单，可重复使用并混用；相对清单路径以当前工作目录为基准，支持 `~` 和环境变量。工作区启动时的当前目录是工具目录，因此可直接在输入框填 `download_list/download_list.yaml`。在仓库根目录用 Windows PowerShell 执行现有清单：

```powershell
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" ".\001_获取B站视频\download_bilibili.py" --url ".\001_获取B站视频\download_list\download_list.yaml"
```

清单顶层的 `date`、`commit` 为可选备注，不参与下载，`download_list` 为非空任务数组，任务必须有 `url`，`title` 只用于日志显示。支持全局及逐项设置 `all-parts`、`merge-parts`、`quality`，优先级为“任务项 → 清单全局 → 显式命令行选项 → 原有默认行为”。`quality` 必须在任务或全局指定：按本任务所有目标 P 的实际可下载档位并集排序，`1` 取最高档作为统一上限，`2` 取次高档；`quality` 策略下各 P 自动取不超过此上限的最高可用档；`merge` 策略按组选择兼容方案。排名不存在时该投稿失败并继续其他任务；某个 P 在上限内没有可用档位时只报该 P 失败。清单不弹出菜单，格式在联网前统一校验，错误包含文件和任务序号。

```yaml
date: "下载备注"
all-parts: true
merge-parts: 0
quality: 1
download_list:
  - title: "日志备注，非文件命名"
    url: "BV1xx411c7mD"
  - url: "BV1yy411c7mD"
    all-parts: false
    merge-parts: -1
    quality: 2
```

清单的 `merge-parts` 兼容数字 `-1`、`0` 和字符串分组表达式，清单自身决定是否下载全部分 P，无需额外附加 `--all-parts`。哪个任务的分 P 先处理完，就先进入合并队列；清单仅使用本次任务选定的画质，不从其他本地画质补齐，也不弹出画质菜单。清晰度优先时若全量拼接涉及不同档位，报告该任务拼接失败；分组合并逐组检查，混合档位的一组失败，其余组继续。重复目标按 BV、分 P、CID、实际画质和格式版本去重传输，保留每项的拼接设置。格式错误返回 `1`，运行中单项失败或主动跳过返回 `2`，成功返回 `0`；Ctrl+C 取消本次运行并保留断点，资源清理完成后返回 `130`。

普通链接同一 BV 的目标分 P 共用一次画质上限选择。菜单按平台档位编号降序列出档位并集，同一档位的 AVC、HEVC、AV1 编码合并展示；清晰度优先时，选择后各 P 自动使用不超过上限的最高实际档位。例如上限选 4K，有杜比视界的 P 仍不超过 4K，最高只有 1080P 的 P 则选择 1080P。输入 `s` 跳过本任务，`q` 或 Ctrl+C 取消，空输入不默认选择。`download.format` 和 `download.format_sort` 只在各 P 已分配的实际档位内选择编码和音频；仅提示会员而没有实际流的档位不会列入菜单。派发前刷新流地址和可用档位，普通投稿及单季仍沿用最初上限，不重新排名、不自动提高上限，也不再次询问；全部关联季的普通番剧链接则按已选逐集排名重新选档。日志显示任务上限或逐集排名，以及各 P 的实际画质；已有高于本次所选画质的历史文件保留，但不用于本次下载后的自动拼接。

`download.mix_quality` 从配置文件严格读取布尔值，控制实际画质放在目录名还是文件名；两种模式均遵循当前任务的逐集排名或画质上限规则。原分 P 与合并成品始终分开保存。

| 配置 | 普通投稿分 P 目录 | 视频文件名示例 |
| --- | --- | --- |
| `false` | `标题_BV号_qn120_4K_超高清_分P/` | `标题_BV号_p1.mp4` |
| `true` | `标题_BV号_分P/` | `标题_BV号_p1_qn120_4K_超高清.mp4` |

合集目录以 `合集标题_合集编号` 为基础，套用相同规则；合并目录使用 `_合并`，开启时合并文件名也追加实际画质。字幕跟随视频的新文件名前缀；索引的 `path`、`file_name` 和 `stem` 同步实际名称。分目录模式的断点保持 `.streams/BV号_p序号/cid内容ID_格式摘要/`，混合模式为 `.streams/BV号_p序号/qn画质编号/cid内容ID_格式摘要/`，不同实际画质不会混用断点。画质后缀追加在扩展名前，保留原名称中已有的 qn 字样。同一目录并不放宽合并限制，不同实际档位的一组仍报告失败，不自动转码。

要手动拼接已经下载的分 P，在“运行和调试”选择“B站：拼接已下载分 P”，输入 BV 号、番剧 ss 号或对应链接及可选范围。范围留空或 `0` 时拼接全部，要求 P1 到最后一 P 均已下载完成。离线模式有多个本地实际画质时选择其中一个，单档时直接使用；即使文件共用目录也不从其他画质补齐缺失 P。旧记录没有总集数时只能检查已有 P 是否从 P1 连续，需自行确认最后一 P。无需登录，旧版未确认画质可独立选择；成品按当前存放模式进入 `_合并` 目录，原分 P 和字幕保留。

自动合并、手动拼接、全量及分组合并共用 `config/config.yaml` 的 `merge.overwrite_existing` 开关，只接受 YAML 布尔值 `true` 或 `false`，运行时以配置文件的实际值为准。先比较本次所选来源与成品索引中的快照：分 P 顺序、重复次数、CID、画质或源文件 SHA-256 变化时始终重新合并；成品缺失、为空、大小与记录不符或来源快照未知时也重新生成。来源相同且成品有效时，`true` 强制重新合并，`false` 保留成品和索引、日志记为“复用”。新媒体先完整生成，再替换旧成品，生成、保存索引失败或取消时保留或恢复旧成品与原索引；更新同一索引条目，不重复追加。开关只控制来源相同时的合并行为，不阻止下载新增或远端换片后的分 P。

例如同一 BV 从 37 P 增加到 38 P，`all-parts: true` 会下载 P38；`merge-parts: 0` 会更新包含全部 38 P 的成品，即使关闭覆盖也会更新。固定表达式 `1-33;34-37` 仍只合并这两个范围，组外新增 P38 不触发它们更新。远端换片以 CID 变化识别；已知本地 CID 与当前原站不一致的 P，必须先完成更新下载才能参与拼接。最新列表中已移除的历史文件保留，但不会混入全量合并。离线合并依据已保存列表和本地文件判断，不联网监测远端更新。

```yaml
merge:
  overwrite_existing: false # 来源相同则复用；来源变化始终更新。true 强制重新合并相同来源。
```

分 P 编号从 `1` 开始，`1` 对应 P1；单独输入 `0` 表示拼接全部，`0` 不能作为组内编号。指定范围时，使用逗号连接片段、`起点-终点` 表示包含首尾的范围、分号分隔不同输出组。例如 `1-5,8,10-12;10-12` 生成 `标题_BV号_p1-5_p8_p10-12.mp4` 和 `标题_BV号_p10-12.mp4` 两份文件（包含 MKV 分 P 时输出 `.mkv`）。严格按输入顺序拼接，不排序、不去重：`3,1,3` 依次拼接 P3、P1、P3，`10-12,1-5` 先拼 P10～P12 再拼 P1～P5。编号必须为正整数，允许分隔符两侧有空白；范围起点不能大于终点，每组至少包含两个片段，重复项计入数量。

命名只压缩相邻递增编号，保留倒序和重复项；同一批次中相同序列第二次起追加 `_2`、`_3`，再次运行时按相同命名及覆盖开关处理各组旧结果。名称或路径超长时报告该组失败，不截断编号序列。各组只检查所选分 P 的完成状态、真实文件及编码兼容性，未选择的分 P 不影响该组。非法表达式、空组、缺失或未完成的分 P、编码不兼容及运行错误均单独报告，其余组继续；最后汇总每组的输入、输出或失败原因，全部成功返回 `0`，存在失败返回 `2`。原分 P、字幕及已成功的拼接文件均保留。

在仓库根目录用 Windows PowerShell 执行分组拼接（替换为已下载视频的 BV 号）；整个表达式必须放在引号中，避免分号被终端解释为命令分隔符：

```powershell
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" ".\001_获取B站视频\download_bilibili.py" --config ".\001_获取B站视频\config\config.yaml" --merge-video "BV1o1JB69Eua" --merge-parts "1-5,8,10-12;10-12"
```

“B站：下载全部分 P”也提供范围输入框：输入分组表达式后，下载结束即按指定分组拼接。某个分 P 下载失败时仍尝试各组，已完成的所选清晰度分 P 可以正常拼接，包含失败或缺失分 P 的组单独报错；下载或拼接存在失败、主动跳过剩余分 P 时退出码为 `2`，取消返回 `130`，全部完成返回 `0`。

`--merge-parts` 可与 `--merge-video`、下载模式的 `--all-parts` 或 YAML 清单输入同用。手动拼接时省略或留空表示拼接全部分 P；普通链接下载全部分 P 时省略或留空均不拼接；清单优先使用任务项及全局的拼接设置。工作区范围输入框对应此参数。旧的 `--auto-merge-parts` / `--no-auto-merge-parts` 已不再支持。

源视频信息按实际目录独立保存：普通投稿每个 `_分P` 目录一份 `video_info.json`；合集仍在目录内按 BV 保存 `BV号_video_info.json`。分目录模式每份源 JSON 只收录对应画质，混合模式同一份可收录多个实际画质，每个条目保留自己的画质编号和名称。媒体 `path` 均为本目录文件名。程序在内存按 BV 聚合同一目录组的源索引；跨目录组重复投稿、同组重复条目或投稿信息冲突仍明确报错。

每个 `_合并` 目录继续独立使用一份 `video_info.json`，`record_type` 为 `merged`，可汇总多个 BV 和多个分组结果。每个合并视频独立保存 BV 号、原地址、标题、UP 主、清晰度、来源分 P 顺序、相对路径、大小、保存时间、时长、分辨率、帧率和音视频编码；不重复登记到源索引。合并媒体参数从最终文件读取，删除源分 P 及其索引后仍可独立读取、刷新索引，并按 mix_quality 双向整理成品目录和文件名，不会重新创建源占位记录。保存时间取文件修改时间并包含时区，无法取得的信息写为 `null` 并记录原因。

合并结果与实际成品分开保存：`files` 只登记已经生成的媒体，`merge_results` 记录每次成功、复用、失败、中断或因分 P 未完成而跳过的合并。结果包含原始分组表达式、来源分 P 顺序、重复组序号、已确认画质及各分 P 档位、开始和结束时间、错误原因；语法错误、缺失分 P、混合画质、编码不兼容等前置校验失败也会记录。结果统一保存到不带画质后缀的基础 `_合并/video_info.json`；混合模式下与成品索引共用该文件，分画质模式下用于汇总各档位的任务结果。重新合并失败时，旧成品及其 `files` 条目保持原状态，另外追加本次失败结果。后续成功重试保留此前失败历史；切换目录布局、移入合集或只刷新媒体信息都保留结果，删除输出根目录的下载日志也不会丢失这些结果。

例如 `BV1o1JB69Eua` 的杜比视界、HDR、4K 在关闭混合模式时分属三个目录和三份 JSON；开启后进入同一 `_分P` 目录及一份 JSON，文件名标记各自实际画质。复制一个目录到另一个下载根目录后可独立读取；缺少所选实际画质的其他 P 时报告缺失。在线取得的投稿标题、总 P 数和当前 CID 列表同步到该投稿已有索引，完成状态和内容指纹归属文件条目。

下载合集成员时，根据原站合集编号复用当前模式的合集目录，将已下载成员的媒体、字幕、断点和索引按需整理；不同合集分别保存，同名目标冲突拒绝覆盖。切换 `download.mix_quality` 后只在访问投稿或合集时迁移相关内容，不在每次启动时整理整个下载库。已有分 P 和合并成品的 CID、格式参数、有效指纹、来源快照及媒体属性保留，迁移不重新下载、转码或拼接；失败或取消回滚媒体和 JSON。无法确认归属的字幕或断点会明确报错并保留原文件。此行为仍只下载当前 BV 的目标 P，不自动下载整个合集。

每份成品使用包含实际画质的独立标识，`source_parts` 和 `source_snapshot` 保留来源顺序、重复次数、CID、实际画质及 SHA-256。源条目的 `source_cid` 表示成功下载版本，`content_fingerprint` 按大小和纳秒修改时间缓存 SHA-256；大小或时间改变才重算，时间变化但内容相同仍可复用。大小和时间均未变的外部改写不在缓存检测范围内。源索引升级为 v8，`mix_quality` 标记磁盘布局；关闭时顶层画质描述本目录，开启时不声明单一画质，各条目保存实际档位。`base_stem` 保存不含新增画质后缀的基础名，支持模式往返恢复。合并索引升级为 v2 和 `record_type: merged`，不参与源投稿定位。

访问 v1～v7 旧源记录时，先按旧记录确认布局，再按当前配置升级为 v8；旧单一源记录拆分或汇入对应目录。新索引核对成功后移除旧索引，写入或移动失败恢复原文件。配置仍为分目录模式时，已经规范保存的媒体不改名或移动；切换为混合模式才归并目录并追加实际画质后缀，切回后恢复基础文件名。没有媒体条目时可暂存基础目录占位索引，分配画质后归入目标目录；最外层文件事务成功后自动清理旧索引留下的空目录。再次访问来源时，即使布局无需变化，也会清理该来源已有的旧空目录；媒体、字幕、断点、其他索引及下载根目录保留，失败回滚前不会清理旧目录。当前源索引目录内尚未写入文件的断点子目录也会保留，断点来源统一识别 BV、ss 和 ep 标识。

解析投稿后、传输开始前创建源投稿记录，在分 P 开始、完成、失败或中断时原子更新；拼接完成后独立更新合并索引；不会随每个下载数据块频繁写盘。再次运行时按 CID、完成状态、格式签名和真实文件判断是否跳过下载。替换已有 P 时，新视频完整封装成功后才通过事务更新媒体、CID 和内容指纹；失败保留旧成功版本，当前更新任务报告失败。缺少 CID 的历史文件不能自动认定为当前版本；用户明确认可现有文件时，可通过 `library.adopt_existing_content` 根据已查询的当前列表补齐来源基线与旧成品快照，保留媒体且无需下载或合并，但不能追认建立基线前的远端换片。旧 `download.json` 中的必要信息会先合并到源记录，写入并核对成功后删除；迁移失败会报错并保留尚未迁移的原记录。

已有下载可在“运行和调试”选择“B站：补生成视频信息”，或者在仓库根目录用 Windows PowerShell 执行：

```powershell
& "C:/ProgramData/miniconda3/envs/test_regression_py3.12/python.exe" ".\001_获取B站视频\download_bilibili.py" --config ".\001_获取B站视频\config\config.yaml" --refresh-metadata
```

该模式扫描配置的下载目录，不需要视频链接，兼容旧分 P 子目录、嵌套清晰度目录及 v1～v3 混放记录，不重新下载或执行拼接。下载、手动拼接和补生成信息访问旧投稿时均按需整理：源视频、字幕、断点流进入 `_分P`，明确标记为 `merged` 的结果进入 `_合并`，并拆分独立索引。未知画质保留 `_旧版_未确认清晰度` 后缀；未登记且无法确认用途的文件保留原位并报告，可补生成信息后再次整理。迁移重算相对路径、清理空旧目录，保留媒体属性及格式签名；同名目标拒绝覆盖，移动或记录保存失败时回滚媒体和相关 JSON。合并索引独立扫描并刷新，不依赖源分 P 或登录；源投稿的 UP 主等信息仍复用认证查询原站，查询失败时保存可确认的本地信息并返回 `2`。`--refresh-metadata` 与登录检查、画质列表、手动拼接模式互斥，不能与 `--url` 或 `--all-parts` 同用。

测试使用模拟原站响应、本地 HTTP/HTTPS 服务及 FFmpeg 短视频；Chrome 用例使用临时无头浏览器，取消用例使用独立进程和真实控制台信号，不读取真实账号或下载目录。HTTPS 取消用例通过已有 OpenSSL 生成临时证书，环境没有 OpenSSL 时只跳过此项；生产运行不依赖该命令。

下载流程按完整画质确认组增量发现：一组投稿/关联季完成目录、各 P 画质查询和确认后，即可进入下载；后续独立组的目录与画质准备在同一个 `max_in_flight` 处理池推进，不再等待全部输入准备完成。普通同源链接及关联季仍合并确认，清单仍按任务的档位并集决定上限，拼接仍先确定组内兼容版本。短链接先解析真实编号，以免重复输入分开确认；普通关联季先读取用于识别重叠关系的关联季索引，关系不对称时仍合并为一次确认。原浏览器只在主线程使用，目录和画质查询通过独立 HTTP 快照进行。日志按组批量登记，页面显示准备是否完成；展开期间已发现数量不是最终总数。取消后停止发现并回收两池，已完成文件保留，正在运行的旧批次不自动重启。
