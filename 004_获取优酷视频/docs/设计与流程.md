# 优酷视频工具设计与流程

本文描述当前实现；运行参数以 `configs/` 中的配置和注释为准，日常操作见 [README](../README.md)。

## 目录与职责

- `decode.py` 定义命令行入口，读取主配置并处理批次退出码；`local/configuration.py` 解析和校验配置。
- `local/tasks.py` 读取链接清单，逐项校验官方节目目录、首播日期和正片集序；`local/youku/` 负责客户端上下文、登录态、原生签名、选源、清单及媒体还原。
- `local/scheduler.py` 负责下载池、共享处理池和字节容量队列；`local/application.py` 协调单集各阶段，`local/download.py` 负责分片下载与断点。
- `local/batch.py`、`local/process.py` 和 `local/storage.py` 分别负责阶段资源与解码验证、外部进程、指纹与发布；`local/journal.py` 负责进度和报告。
- `configs/` 保存正式配置，`download_list/` 保存清单，`tests/` 保存隔离测试，`research/client_svip_4k/` 保存专项研究、配置与验证记录。

## 下载与处理流程

1. 入口读取主配置和链接清单，持有优酷专用输出及工作目录锁；客户端需已登录并初始化播放器。工具读取客户端上下文和登录态，校验原生模块摘要，再使用已验证接口请求官方数据。
2. 清单按顺序逐项展开，每部剧先校验官方节目身份、首播日期和完整分页，再按集序交接已上线正片；重复视频和画质组合只调度一次，保留清单分组归属。清单中的画质和整剧选项可覆盖主配置。
3. 逐集确认正片、音轨和授权，按配置语言优先级选音轨，再按分辨率面积及声明大小排名画质。清单、播放接口和流的时长须符合校验要求；选中档位或格式不可用时明确失败，不自动降档。当前仅支持经过验证的原始音源档位和帧享 4K HLS/TS 媒体适配。
4. 检查已登记成品的来源身份、验证证明及指纹：`reuse_check: full` 重算 SHA-256，`fast` 按配置使用已校验的大小和修改时间，属性变化时重新计算。符合条件的成品跳过下载；可验证的候选成品也可从后处理继续。
5. 其余任务顺序下载单集分片，按来源身份隔离工作现场，对已有分片重新校验摘要后续传。分片地址过期时在处理池重新解析并验证来源，再排队下载；来源变化保留旧现场，在配置的次数范围内重新处理。
6. 下载完成后交接处理池：按完整 PES 还原原始媒体并规范连续计数，根据不连续区间无重编码封装及拼接 MP4；对照封装前后的音视频规格，再用启用的 CPU 或 GPU 槽完整解码视频和音轨，验证帧及完整时长。
7. 发布前复核来源并计算候选指纹；按配置命名，校验复制并登记索引。已有同名文件不覆盖，必要时生成区分名称。成功后按配置清理或保留媒体中间文件；失败或取消保留现场和可靠断点。

## 并发、队列与取消

- `download.threads` 限制同时下载的剧集数，每集内顺序下载分片；目录发现、选源、复用检查、续签、还原、封装、验证、发布和清理共用顶层 `max_in_flight` 处理上限。还原、封装、来源复核、发布和各启用的解码设备另有内部槽。
- `download.queue_capacity_gb` 按实际字节限制下载完成、等待后处理的媒体队列，容量按 1024³ 字节换算；单集超限时可独占空队列。等待入队时暂停派发新下载，进入处理后释放队列容量；预解析也受限，队列容量不是工作目录的总磁盘限额。
- 认证恢复耗尽或账号变化时停止派发新任务，已下载任务继续处理；单项失败记录原因并继续其他任务。Ctrl+C 取消批次并保留可靠断点；成功返回 0，失败或跳过返回 1，用户取消返回 130。

## 格式与记录边界

- 仅处理当前配置和客户端版本已验证的优酷媒体、签名与还原接口；客户端升级、模块摘要不匹配、未知保护方式或未验证格式均需重新验证，不沿用其他平台的格式假设。
- 登录态、签名媒体地址及密钥用于内存中的请求和还原，不写入断点或来源记录；断点和报告记录脱敏的来源身份、摘要与阶段信息。
- 实时日志仅在本机回环地址提供，结束后生成离线报告；输出与工作目录使用独立锁，索引和日志与其他工具隔离。研究过程及已验证结果见 [研究记录](../research/client_svip_4k/FINDINGS.md)。

## 验证

`tests/` 中的隔离测试覆盖清单发现、协议、流水线、并发调度、共享输出及入口；专项研究测试位于 `research/client_svip_4k/tests/`。涉及真实客户端、账号或媒体的验证应按研究配置和实际授权环境执行，不以隔离测试结果替代实机验证。
